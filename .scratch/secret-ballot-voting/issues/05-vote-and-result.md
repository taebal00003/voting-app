# 05: 투표자가 투표하고 결과를 본다

**What to build:** 명부에 있는 투표자가 코드로 입장해 투표를 고르고, 선택지 하나에 투표한 뒤 결과(표 수, 비율, 총 참여 수)를 본다. 1인 1표와 비밀 투표가 보장되고, 운영자는 참여 현황을 이름순으로만 본다. 동작은 이미 구현되어 있으므로, 이 티켓은 그 보장을 테스트로 고정하고, 테스트에서 드러난 버그를 고친다. 스펙: 사용자 스토리 8~28, 56~58, 60. 결정 기록 0001과 0002를 따른다.

**Blocked by:** 03, 04

**Status:** resolved

- [x] 다음 동작을 테스트한다.
  - 정상 투표는 `ok`이고, 그 선택지의 표 수가 1 늘고, 투표자 목록에 "투표 완료"로 표시됨
  - 같은 투표자의 두 번째 투표는 `already`이고, 표 수는 그대로
  - 같은 투표자의 동시 요청 두 개 중 정확히 하나만 `ok`
  - 다른 투표의 선택지로 투표하면 `gone`이고, 참여 기록이 남지 않음
  - 없는 투표나 잘못된 형식의 ID는 오류 없이 `gone`
  - 여러 투표자가 투표했을 때 표 수 합계와 참여 수가 같음
  - 참여 현황은 참여/미참여 이름을 이름순으로 돌려줌
  - 명부에서 뺀 투표자의 참여 기록과 표는 결과에 남음
  - 비밀 투표: 스키마에 투표자와 선택지를 함께 참조하는 테이블이나 열이 없음. 스펙이 허용한 유일한 스키마 수준 테스트다.
- [x] 투표 전 화면으로는 선택지 ID와 문구만 전달되고, 표 수는 클라이언트로 가지 않는다. 코드 리뷰로 확인하고, 가능하면 투표 전 페이지 응답에 표 수가 없는지 HTTP로 확인한다.
- [x] 결과는 새로고침할 때만 갱신된다. 폴링이나 실시간 갱신은 추가하지 않는다(스펙의 Out of Scope).
- [x] 타입 검사, lint, 빌드, 테스트가 통과한다.
