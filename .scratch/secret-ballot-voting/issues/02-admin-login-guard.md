# 02: 운영자 로그인과 운영자 경로 가드

**What to build:** 운영자는 공용 운영자 비밀번호로 로그인하고 로그아웃한다. 로그인하지 않은 사람이 운영자 경로에 들어오면 한 곳(`proxy`)에서 일괄로 로그인 화면으로 보내서, 앞으로 추가될 운영자 화면도 자동으로 보호된다. 로그인과 로그아웃은 이미 구현되어 있으므로, 이 티켓은 가드를 추가하고 기존 동작을 스펙(사용자 스토리 29~35)에 맞게 확인한다.

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] Next 16의 `proxy` 규약(구 middleware)으로 운영자 경로 전체를 가드한다. 로그인 화면 자체는 가드에서 제외한다. 먼저 `node_modules/next/dist/docs/`에서 proxy 문서를 읽는다.
- [x] 가드가 있어도 운영자 페이지와 운영자용 Server Action 안의 권한 확인은 그대로 둔다. Server Action은 직접 POST로도 호출될 수 있기 때문이다.
- [x] 세션은 7일 유지된다. 서명 키는 운영자 비밀번호 그대로이므로, 비밀번호를 바꾸면 기존 로그인이 모두 무효가 된다. `SESSION_SECRET` 같은 별도 키는 추가하지 않는다.
- [ ] 비밀번호가 틀리면 안내 문구가 나오고, 로그아웃하면 로그인 화면으로 간다. (구현되어 있고 코드로 확인했지만 브라우저로 눌러보지는 않음. 사람이 한 번 확인할 것)
- [x] 로그인하지 않고 운영자 경로에 접근하면 로그인 화면으로 가고, 로그인 화면에 접근하면 200이다. 운영 빌드를 띄워 HTTP 요청으로 확인한다.
- [x] 타입 검사, lint, 빌드가 통과한다.

    - 다른 비밀번호로 서명한 토큰과 만료된 토큰은 307로 로그인 화면에 간다.
    - 투표자 화면은 200으로 영향이 없다.
  - 로그인 폼 제출(Server Action)은 브라우저로 확인하지 않았다.
